# Proposed analytical model and current source coverage

The target dimensions and facts are `dim_lgu`, `dim_cmci_indicator`, `fact_cmci_indicator`, `fact_population`, `fact_ldrrmf`, and `fact_earthquake_event`. The owner has set the analysis geography to cities and municipalities; the former barangay population fact is not part of this target. `fact_population` now represents one PSA city/municipality source path and census year, with a nullable PSGC match.

The Silver mappings added for the available sources prepare values for that model while preserving lineage. They do not rename or manufacture Gold keys. PSGC codes are available from PSGC and the reviewed `lgu_master`; CMCI uses the approved `cmci_lgu_map`. LDRRMF currently has only region, province, LGU name, and type, so it remains unmatched until a reviewed location mapping exists. PHIVOLCS events retain source location text and do not receive an LGU match in Silver.

PSA population is available at national, region, province, and city/municipality levels in the documented 2024 extract. Gold uses only city/municipality rows and matches exact LGU and province names to the active reviewed `lgu_master`. Unmatched and ambiguous records retain their source geographic path and have null `psgc_code`; no name similarity or population allocation is used. Other PSA hierarchy rows stay in Silver for coverage/audit and are not mixed into the Gold fact.

The current Gold build creates `dim_lgu`, `dim_cmci_indicator`, `fact_cmci_indicator`, `fact_population`, `fact_ldrrmf`, and `fact_earthquake_event`. `fact_population` retains each city/municipality source row, linking only unique exact LGU + province name matches; it is keyed by the PSA `geographic_location` and year so unmatched rows remain observable. `fact_ldrrmf` includes city and municipality rows only; province lines remain in Bronze and Silver, and the Gold quality run counts this intentional exclusion. LDRRMF and PHIVOLCS retain null PSGC/match fields until approved matching decisions; LDRRMF `utilization_rate` remains null until its formula is approved.

This change does not calculate `population_exposure_score`, `earthquake_activity_score`, `risk_score`, `risk_level`, `preparedness_score`, or `preparedness_gap`. Before Platinum implementation, the project owner must approve population and earthquake inputs, their normalization/units/weights/time window, risk cutoffs, selected CMCI capacity indicators and scale, LDRRMF utilization formula and zero-appropriation behavior, missing-component behavior, and preparedness-gap ranking direction. The proposed highest-to-lowest gap ordering conflicts with the fact that a more negative `preparedness_score - risk_score` can indicate a greater shortfall.
