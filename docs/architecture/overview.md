# Pipeline layers and source mappings

AHON keeps source evidence in Bronze, applies source-specific typing and field mapping in Silver, builds the approved dimensions and facts in Gold, and produces question-specific analysis in Platinum. Dataset jobs live beside each source under `src/sql/datasets/`; shared Silver and monitoring jobs live under `src/sql/02_silver_clean/` and `src/sql/monitoring/`.

Current Bronze tables are BLGF LDRRMF, PSA population, PHIVOLCS earthquake events, PSGC API records, and the two CMCI raw response/indicator tables. Their Silver destinations are documented in [the data dictionary](data-dictionary/README.md). The PSGC Silver table is versioned staging; `ahon.reference.lgu_master` remains the reviewed active-LGU reference.

The analytical geography is cities and municipalities. `dim_lgu` uses active `lgu_master` with PSGC Silver enrichment by exact code. PSA population is built to a city/municipality-year fact using exact LGU and province names against active `lgu_master`; non-matches and ambiguous names retain their source path and null PSGC code. Province rows remain in LDRRMF Bronze and Silver but are excluded from the city/municipality Gold fact with an explicit DQ count. BLGF rows remain unmatched because approved name matching is not available. PHIVOLCS location strings do not establish an LGU match.

Risk, preparedness, vulnerability, and priority metrics are not calculated by these source-layer jobs. Their normalization, weights, thresholds, missing-value policy, and preparedness-gap ranking direction remain unresolved in project materials.

## Gold build and Platinum readiness

Run `src/sql/00_setup/07_gold_setup.sql`, then `src/sql/gold/build_gold.py`; run `src/sql/monitoring/silver_gold_quality.py` after the Silver and Gold builds. Gold snapshots are deterministic and rerunnable. Unmatched BLGF and PHIVOLCS rows remain present with null PSGC keys; PSA rows remain at city/municipality grain and exact-name nonmatches retain null PSGC. LDRRMF province rows remain in Silver and are reported as an explicit Gold scope exclusion.

Platinum table candidates are `risk_level_by_lgu`, `preparedness_gap_by_lgu`, `vulnerability_priority_by_lgu`, and `cmci_preparedness_priority_by_lgu`. No Platinum table is built until the project approves: (1) population and earthquake component selection, normalization, units, weights, missing-value rules, and time window; (2) risk-level cutoffs; (3) CMCI capacity indicator selection and score scale; (4) LDRRMF utilization-rate formula and zero-appropriation handling; and (5) preparedness-gap direction/scale and the exact high-risk/low-preparedness thresholds. The supplied “highest to lowest” sort conflicts with the intuition that a more negative `preparedness_score - risk_score` indicates a greater shortfall.

## Deployment state

The repository has no `databricks.yml`, job resource, configured warehouse/cluster, or secret-scope settings. These scripts are callable in Databricks in the documented order, but no scheduled job is declared or deployment is claimed. The CMCI mapping bootstrap, PSGC token access, source landing, and environment catalog selection also require workspace-specific setup before a full automated run.
