# Pipeline layers and source mappings

AHON keeps source evidence in Bronze, applies source-specific typing and field mapping in Silver, builds the approved dimensions and facts in Gold, and produces question-specific analysis in Platinum. Dataset jobs live beside each source under `src/sql/datasets/`; shared Silver and monitoring jobs live under `src/sql/02_silver_clean/` and `src/sql/monitoring/`.

Current Bronze tables are BLGF LDRRMF, PSA population, PHIVOLCS earthquake events, PSGC API records, and the two CMCI raw response/indicator tables. Their Silver destinations are documented in [the data dictionary](data-dictionary/README.md). The PSGC Silver table is versioned staging; `ahon.reference.lgu_master` remains the reviewed active-LGU reference.

The analytical geography is cities and municipalities; barangay population is out of scope. `dim_lgu` uses active `lgu_master` with PSGC Silver enrichment by exact code. PSA population is built to a city/municipality-year fact using exact LGU and province names against active `lgu_master`; non-matches and ambiguous names retain their source path and null PSGC code. BLGF uses the same approved exact-name-and-province matching rule; ambiguous and unmatched rows remain with null PSGC. Province rows remain in LDRRMF Bronze and Silver but are excluded from the city/municipality Gold fact with an explicit DQ count. PHIVOLCS events are spatially matched against the approved approximate Geoportal city/municipality boundaries; ambiguous and unmatched events remain visible with null PSGC and confidence.

Experimental Platinum v1 calculates risk, preparedness, vulnerability, and CMCI priority outputs using owner-approved assumptions. They are not production-calibrated metrics: population and event scores use cross-sectional percentiles, risk-level and vulnerability categories use tertiles, CMCI capacity averages percentiles across approved indicators, and preparedness requires both CMCI and LDRRMF components. See [Platinum analytics](data-dictionary/platinum_analytics.md) for formulas, null behavior, and limitations.

## Gold build and Platinum readiness

Run the DAB job in its dependency order, or manually run setup, source ingestion, Bronze validation, Silver transforms, boundary ingestion, Gold build, Silver/Gold validation, then Platinum. Silver tasks wait for the blocking Bronze validation task. Snapshots are deterministic and rerunnable; Bronze boundary versions are retained by source reference and row hash. Exact-name nonmatches, ambiguous names, and spatially ambiguous events remain present with null PSGC; LDRRMF province rows stay in Silver and are counted as a Gold scope exclusion. Platinum snapshots are written separately; after a partial failure, compare their `run_id` values and rerun the complete Platinum task before using the set together.

Platinum outputs are `risk_level_by_lgu`, `preparedness_gap_by_lgu`, `vulnerability_priority_by_lgu`, and `cmci_preparedness_priority_by_indicator`. They implement the approved experimental v1 assumptions, including percentile components, a five-year event window, tertile categories, null missing components, and descending preparedness-gap sort. Risk (0–10,000) and preparedness (0–200) are not on comparable scales, so the gap is an experimental ranking aid, not a calibrated comparison. Zero-event LGUs have unknown magnitude/proximity components and therefore null activity/risk scores.

## Deployment state

The repository now includes a Databricks Asset Bundle job in `databricks.yml` and `resources/ahon_pipeline.yml`. Workspace auth, node type, PSGC secret identifiers, and source-volume inputs remain deployment settings. The active `lgu_master`, reviewed CMCI locality mapping, and GeoPortal boundary GeoJSON must be present before the workflow completes. Disclose the approximate boundary limitation wherever outputs are presented.
